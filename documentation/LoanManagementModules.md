Below is a short API documentation for the three modules, based on the structure we have implemented.

# Loan Management API Documentation

Base URL:

```text
/api/v1
```

All endpoints require authentication unless stated otherwise.

---

# 1. Payments

Payments are used to record customer loan repayments. A payment is linked to a loan and, optionally, a specific repayment schedule.

## Create Payment

**POST**

```text
/api/v1/payments
```

### Sample Request

```json
{
  "loanId": "7f4c8c8a-8f0d-4e42-9f3e-3f8d5e123456",
  "scheduleId": "3a7d5c21-4b7e-4d11-9a32-123456789abc",
  "amount": 1500,
  "paymentMethod": "MPESA",
  "transactionReference": "QWE123456",
  "notes": "Loan repayment"
}
```

### Sample Response

```json
{
  "success": true,
  "message": "Payment recorded successfully",
  "data": {
    "id": "8b2d1c11-1234-4567-8901-abcdef123456",
    "paymentReference": "PAY-20260928-A12B3C",
    "amount": "1500.00",
    "paymentMethod": "MPESA",
    "transactionReference": "QWE123456",
    "status": "COMPLETED",
    "paymentDate": "2026-09-28T15:30:00.000Z",
    "loanId": "7f4c8c8a-8f0d-4e42-9f3e-3f8d5e123456",
    "scheduleId": "3a7d5c21-4b7e-4d11-9a32-123456789abc"
  }
}
```

The payment automatically updates:

* Repayment schedule amount paid/outstanding balance
* Repayment schedule status
* Loan amount paid/outstanding balance
* Loan status
* Loan transaction history

## Get Payments for a Loan

**GET**

```text
/api/v1/payments/loan/:loanId
```

Example:

```text
GET /api/v1/payments/loan/7f4c8c8a-8f0d-4e42-9f3e-3f8d5e123456
```

Returns all payments associated with the specified loan.

# 2. Loan Transactions

Loan transactions provide an audit trail of financial activity on a loan.

Transactions can be generated by activities such as:

* Loan disbursement
* Repayment
* Interest
* Fees
* Penalties
* Refunds
* Adjustments

Customers should normally **view** transactions rather than create them directly.

## Get My Transactions

**GET**

```text
/api/v1/loan-transactions/me
```

### Sample Response

```json
{
  "success": true,
  "data": [
    {
      "id": "11111111-2222-3333-4444-555555555555",
      "transactionNumber": "TXN-20260928-ABC123",
      "type": "REPAYMENT",

      "description": "Loan repayment",

      "balanceBefore": "3000.00",
```

# 3. Loan Status / Overdue

This module handles the current status of loans and identifies loans whose repayment period has expired.

### Loan Statuses

```text
PENDING_DISBURSEMENT
ACTIVE
PARTIALLY_PAID
FULLY_PAID
OVERDUE
DEFAULTED
WRITTEN_OFF
CANCELLED
```

## Get Loan Status

**GET**

```text
/api/v1/loan-status/:loanId
```

### Sample Response

```json
{
  "success": true,
  "data": {
    "loanId": "7f4c8c8a-8f0d-4e42-9f3e-3f8d5e123456",
    "loanNumber": "LN-20260920-ABC123",
    "status": "ACTIVE",
    "principalAmount": "3000.00",
    "totalAmount": "3300.00",
    "amountPaid": "1500.00",
    "outstandingAmount": "1800.00",
    "disbursedAt": "2026-09-20T10:00:00.000Z",
    "maturityDate": "2026-10-04T10:00:00.000Z"
  }
}
```

The frontend can use `maturityDate` to display the **repayment countdown**.

---

## Update Overdue Loans

**PATCH**

```text
/api/v1/loan-status/update-overdue
```

This endpoint checks active/partially-paid loans whose maturity date has passed and changes their status to `OVERDUE`.

### Sample Response

```json
{
  "success": true,
  "message": "Overdue loans updated successfully",
  "data": {
    "updatedLoans": 3
  }
}
```

This endpoint can later be called automatically by a **scheduled background job**, so staff do not have to manually trigger it.

# Overall Flow

The three modules work together like this:

```text
Loan Disbursed
      ↓
Loan Status = ACTIVE
      ↓
Repayment Schedule Created
      ↓
Customer Makes Payment
      ↓
Payment Recorded
      ↓
Loan Transaction Created
      ↓
Loan Balance Updated
      ↓
Loan Status Updated
      ↓
Maturity Date Reached
      ↓
Loan Status = OVERDUE
```

So, for example, if a customer receives a **KSh 3,000 loan**, the system can track the entire lifecycle:

```text
DISBURSEMENT
KSh 3,000
     ↓
Loan Transaction: DISBURSEMENT
     ↓
Customer pays KSh 1,500
     ↓
Payment: COMPLETED
     ↓
Loan Transaction: REPAYMENT
     ↓
Outstanding: KSh 1,800
     ↓
Loan Status: PARTIALLY_PAID
     ↓
Maturity date passes
     ↓
Loan Status: OVERDUE
```

This gives you a clean separation between **money received (Payments)**, **financial history (Loan Transactions)**, and **the current condition of the loan (Loan Status/Overdue)**.
